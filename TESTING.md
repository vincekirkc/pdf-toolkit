# PDF Toolkit - Performance Testing Guide\n\n## Setup\n\n### 1. Install Dependencies\n\n```bash\n# From repository root\npnpm install\n\n# Build all packages\npnpm build\n```\n\n### 2. Start Web App\n\n```bash\ncd apps/web\npnpm dev\n```\n\nOpen [http://localhost:3000](http://localhost:3000)\n\n---\n\n## Test Files\n\nYou'll need PDF test files of various sizes. Here's how to generate them:\n\n### Option A: Use Online PDF Generators\n- [ILovePDF](https://www.ilovepdf.com/) - Can generate sample PDFs\n- [PDF Sample](http://pdf.sample.com/) - Free sample PDFs\n- Generate your own with your own documents\n\n### Option B: Generate Test PDFs Locally\n\nIf you have Python and reportlab installed:\n\n```python\n# generate_test_pdfs.py\nfrom reportlab.pdfgen import canvas\nfrom reportlab.lib.pagesizes import letter\nimport os\n\ndef generate_pdf(filename, num_pages, page_size=(8.5, 11)):\n    \"\"\"Generate a simple PDF with text and shapes\"\"\"\n    c = canvas.Canvas(filename, pagesize=letter)\n    \n    for i in range(num_pages):\n        # Add page content\n        c.setFont(\"Helvetica-Bold\", 24)\n        c.drawString(50, 750, f\"Page {i + 1}\")\n        \n        c.setFont(\"Helvetica\", 12)\n        for j in range(20):\n            c.drawString(50, 700 - (j * 25), f\"Sample text line {j + 1}\")\n        \n        # Add shapes\n        c.rect(50, 100, 200, 100, fill=True)\n        c.circle(400, 400, 50, fill=False)\n        \n        c.showPage()\n    \n    c.save()\n    size_mb = os.path.getsize(filename) / (1024 * 1024)\n    print(f\"Generated {filename}: {num_pages} pages, {size_mb:.2f} MB\")\n\n# Generate test suite\ngenerate_pdf(\"test-5mb-5pages.pdf\", 5)\ngenerate_pdf(\"test-10mb-20pages.pdf\", 20)\ngenerate_pdf(\"test-20mb-50pages.pdf\", 50)\ngenerate_pdf(\"test-50mb-100pages.pdf\", 100)\n```\n\n---\n\n## Test Scenarios\n\n### 🧪 Test 1: Merge PDFs\n\n**Purpose:** Validate merge performance with multiple file combinations\n\n**Test Cases:**\n\n| Case | Files | Total Size | Expected Duration | Sub-2s? |\n|------|-------|------------|-------------------|----------|\n| Small merge | 2 × 5MB | 10MB | ~150ms | ✅ |\n| Medium merge | 3 × 10MB | 30MB | ~300ms | ✅ |\n| Large merge | 4 × 20MB | 80MB | ~600ms | ✅ |\n| XL merge | 5 × 20MB | 100MB | ~900ms | ✅ |\n\n**Steps:**\n1. Open http://localhost:3000\n2. Select \"Merge\" operation\n3. Upload test PDF files\n4. Click \"Merge\"\n5. **Record:**\n   - ⏱️ Duration (shown in UI)\n   - 💰 Cost (shown in UI)\n   - ✅ Success/failure\n   - Open browser DevTools (F12) → Console\n   - Look for `[OperationCost]` logs\n\n**Expected Console Output:**\n```\n[OperationCost] {\n  operation: \"merge\",\n  duration: \"245.34ms\",\n  pages: 42,\n  size: \"15.23MB\",\n  cost: \"$0.000187\",\n  route: \"client\"\n}\n```\n\n---\n\n### 🧪 Test 2: Split PDFs\n\n**Purpose:** Validate split performance for various page counts\n\n**Test Cases:**\n\n| Case | File | Pages | Chunk Size | Expected Duration | Sub-2s? |\n|------|------|-------|------------|-------------------|----------|\n| Single split | 20 pages | 20 | 1 | ~180ms | ✅ |\n| Medium split | 50 pages | 50 | 1 | ~400ms | ✅ |\n| Large split | 100 pages | 100 | 1 | ~800ms | ✅ |\n| Chunked (5-page) | 100 pages | 20 chunks | 5 | ~700ms | ✅ |\n\n**Steps:**\n1. Select \"Split\" operation\n2. Upload a PDF (e.g., 50+ pages)\n3. Set \"Pages per chunk\" to 1 (or higher for chunking)\n4. Click \"Split\"\n5. **Record:**\n   - ⏱️ Duration\n   - 📊 Number of chunks created\n   - ✅ All pages download correctly\n   - Check console for logs\n\n**Expected Result:**\n- Should create N separate PDFs (one per page or chunk)\n- Each page should be downloadable\n- Total duration should be < 2s even for 100+ page PDFs\n\n---\n\n### 🧪 Test 3: Rotate PDFs\n\n**Purpose:** Validate rotation performance\n\n**Test Cases:**\n\n| Case | File | Pages | Degrees | Expected Duration | Sub-2s? |\n|------|------|-------|---------|-------------------|----------|\n| Small rotate | 5MB | 5 | 90 | ~120ms | ✅ |\n| Medium rotate | 10MB | 20 | 90 | ~180ms | ✅ |\n| Large rotate | 50MB | 100 | 90 | ~500ms | ✅ |\n| Full rotate | 20MB | 50 | 180 | ~250ms | ✅ |\n\n**Steps:**\n1. Select \"Rotate\" operation\n2. Upload a PDF\n3. Select rotation degree (90°, 180°, 270°)\n4. Click \"Rotate\"\n5. **Record:**\n   - ⏱️ Duration\n   - 👁️ Visual verification (download and open)\n   - ✅ All pages rotated correctly\n\n**Expected Result:**\n- Pages should be visibly rotated\n- Metadata should be updated (not re-encoded)\n- Fast operation (< 500ms even for large PDFs)\n\n---\n\n### 🧪 Test 4: Compress PDFs\n\n**Purpose:** Validate compression and estimate savings\n\n**Test Cases:**\n\n| Case | File | Size | Quality | Estimated Ratio | Expected Duration | Sub-2s? |\n|------|------|------|---------|-----------------|-------------------|----------|\n| Light compress | 10MB | 10MB | High | 95% | ~150ms | ✅ |\n| Medium compress | 10MB | 10MB | Medium | 88% | ~200ms | ✅ |\n| Heavy compress | 10MB | 10MB | Low | 85% | ~250ms | ✅ |\n| Large compress | 50MB | 50MB | Medium | 88% | ~800ms | ✅ |\n\n**Steps:**\n1. Select \"Compress\" operation\n2. Upload a PDF (ideally with images)\n3. Select quality level (High/Medium/Low)\n4. Click \"Compress\"\n5. **Record:**\n   - ⏱️ Duration\n   - 📊 Original vs. compressed size (download and check file size)\n   - 💾 Compression ratio: `compressed_size / original_size`\n   - 👁️ Visual quality (open downloaded file)\n\n**Expected Result:**\n- Compressed file should be slightly smaller (stream optimization)\n- NOTE: Real image compression requires server-side processing\n- Current implementation is stream-level only\n\n---\n\n## Performance Benchmarks\n\n### Target Metrics\n\nAll operations should maintain:\n\n✅ **Duration:** < 2000ms (most < 500ms)  \n✅ **Cost:** < $0.001 per operation  \n✅ **Success Rate:** 100%  \n✅ **Memory:** < 500MB peak usage  \n\n### Expected Results Table\n\n```\nOperation    | File Size | Pages | Duration | Cost      | ✅/❌\n-------------|-----------|-------|----------|-----------|-------\nMerge 2×10MB | 20MB      | 40    | ~250ms   | $0.00025  | ✅\nMerge 5×20MB | 100MB     | 200   | ~900ms   | $0.00090  | ✅\nSplit 50pg   | 10MB      | 50    | ~400ms   | $0.00040  | ✅\nSplit 100pg  | 20MB      | 100   | ~800ms   | $0.00080  | ✅\nRotate 20MB  | 20MB      | 50    | ~200ms   | $0.00020  | ✅\nCompress 10MB| 10MB      | 20    | ~200ms   | $0.00020  | ✅\n```\n\n---\n\n## Monitoring Console Logs\n\nOpen DevTools (F12) and check the **Console** tab. Every operation logs:\n\n```javascript\n[OperationCost] {\n  operation: \"merge|split|rotate|compress\",\n  duration: \"XXms\",\n  pages: N,\n  size: \"X.XXMB\",\n  cost: \"$X.XXXXXX\",\n  route: \"client\"\n}\n```\n\n**What to look for:**\n- ✅ All logs appear successfully\n- ✅ Duration is consistent across runs\n- ✅ Cost calculation is reasonable\n- ❌ Any errors or missing logs\n\n---\n\n## Test Checklist\n\n- [ ] Merge 2 small PDFs (~5MB each) - Expected: ~150ms\n- [ ] Merge 5 large PDFs (~20MB each) - Expected: ~900ms\n- [ ] Split 50-page PDF - Expected: ~400ms\n- [ ] Split 100-page PDF - Expected: ~800ms\n- [ ] Rotate 50-page PDF - Expected: ~200ms\n- [ ] Compress 10MB PDF - Expected: ~200ms\n- [ ] Verify all downloads work\n- [ ] Check console logs for all operations\n- [ ] Confirm no errors or failures\n- [ ] Validate sub-2s claim for all tests\n\n---\n\n## Stress Test (Optional)\n\nIf all basic tests pass, try these edge cases:\n\n```\n1. Merge 10 × 20MB PDFs (200MB total) - Should complete in ~2s\n2. Split 200-page PDF - Should handle gracefully\n3. Compress already-compressed PDF - Should not error\n4. Rapid successive operations - Should handle queue/concurrency\n5. Very large single PDF (50MB+) - Check memory usage\n```\n\n---\n\n## Troubleshooting\n\n### Operation times exceed 2s\n- ❌ Likely browser/machine limitations, not code\n- Check browser task manager for other processes\n- Try in an incognito/private window\n- Modern browsers: Chrome > Firefox > Safari (sometimes)\n\n### Logs not appearing in console\n- ❌ Instrumentation logger not configured\n- Open DevTools Console before running operation\n- Clear console and retry\n- Check for any JavaScript errors\n\n### Downloads fail\n- ❌ Browser download settings issue\n- Check browser download folder\n- Try a different browser\n- Check if file size is too large\n\n### Memory issues\n- ❌ Only with very large files (100MB+)\n- Current implementation loads entire PDF in memory\n- For production: Implement streaming/chunked processing\n\n---\n\n## After Testing\n\nOnce you've validated all operations:\n\n1. **Document Results** - Create `PERFORMANCE.md` with actual timings\n2. **Adjust Costs** - Update `COST_CONFIG` in `packages/operations/src/cost-estimator/index.ts`\n3. **Move to Phase 2** - Integrate Clerk for user authentication\n4. **Database Integration** - Connect Supabase for persistent logging\n\n---\n\n## Quick Test Script\n\nIf you want to automate some testing:\n\n```javascript\n// Paste in browser console while on http://localhost:3000\n\nconst testResults = [];\n\nfunction logResult(operation, duration, success) {\n  testResults.push({ operation, duration, success, timestamp: new Date() });\n  console.table(testResults);\n}\n\n// After each operation, run:\n// logResult('merge', durationMs, true)\n\nconsole.log('Test logger ready.
